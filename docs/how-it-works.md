# 鼓声与节拍是怎样产生的

Drum 808 不播放录音。每次击打都在指定的音频时间创建振荡器或噪声源，再用滤波器塑造频谱，用包络决定声音如何出现和消失。每个声部接受音频上下文、输出节点、开始时间、力度和参数，因此同一套代码既能实时播放，也能放进 `OfflineAudioContext` 检查渲染结果。

## 八种鼓声

**底鼓 BD** 用正弦波。起音频率从约 145–180 Hz 很快降到 48 Hz，最后落到 43 Hz，形成鼓皮受击后松弛的感觉。指数音量包络让低频自然衰减。力度越大，起音音高略高、尾音略长；衰减滑块改变整体长度。

**军鼓 SD** 把 180 Hz 的三角波、330 Hz 的正弦波与高通滤波后的白噪声相加。振荡器是鼓腔，噪声是响弦。响弦滑块改变噪声比例和高通频率；重音也会略微增加亮度和尾音。

**闭镲 CH 与开镲 OH** 共享六个非整数倍关系的方波振荡器，经带通和高通滤波，只留下明亮、金属感的高频。闭镲约 55 毫秒，开镲的衰减可调。引擎给开镲单独的增益门；闭镲或新的开镲到来时，旧门在 8 毫秒内降到近乎无声，避免瞬间切断带来的咔哒声。同一步同时有开闭镲时，闭镲优先。

**拍手 CP** 是带通噪声。前三个短促包络相隔约 12 毫秒，模拟多只手并非完全同步的拍击，再接一个较轻的扩散尾音。

**低嗵鼓 LT** 是从 155 Hz 降到 82 Hz 的正弦波，叠加极短的低通噪声作为鼓槌起音。**边击 RS** 用 480 Hz 三角波和 1760 Hz 方波穿过带通滤波器，再以很短的包络收尾。**牛铃 CB** 用 540 Hz 与 803 Hz 两个不完全成整数比的方波，经带通滤波和短衰减，得到有棱角的双音金属声。

力度保存在 pattern 中，是 0 / 1 / 2 / 3 四个等级，分别映射到 0 / 0.35 / 0.75 / 1 的振幅系数。0 不创建任何声音节点。包络的终点是极小的正数，避免指数曲线无法到达零的问题；结束后所有源会停止并断开，最后一个源释放其余节点。

## 为什么节拍不会随页面计时器漂移

页面定时器只是“叫醒调度器”，不是“现在敲一下鼓”。Worker 大约每 25 毫秒发出一次消息，调度器查看 `AudioContext.currentTime`，把未来 110 毫秒内的音符提前交给 Web Audio，使用绝对音频时间播放。下一步的时间由前一步的时间累加得到，不把每次计时器迟到的误差加进去。Worker 不可用时改用递归 `setTimeout`，音符仍使用同一个音频时钟。

四四拍每小节时长是 `240 / BPM` 秒；平直一步是小节时长除以 `stepsPerBar`。Swing 把相邻两步的时间分成 `2 × 一步 × Swing比例` 和 `2 × 一步 × (1 − Swing比例)`：50% 对半分，75% 是 3:1。偶数步起点不变，奇数步被推迟，两步总时长不变。因此 12、16、24 步都不会越摇越长。BPM、Swing 和编辑在下一个未进入预调度窗口的音符生效，已交给音频线程的音符保留原定时间。

页面卡顿或后台停留过久时，时钟直接前进到当前时间之后，跳过错过的音符。播放光标也不听计时器指挥：调度器记录每步的音频时间，动画帧读取队列，仅在音频时间到达后显示该步。停止会清空队列和光标，淡出旧输出总线；再次播放总从第零步开始。

各轨经过自己的增益节点，静音、独奏、音量改变都有 8 毫秒渐变。主输出先留出余量，经过快速压缩器，再用软峰值曲线约束最初的瞬态，防止叠加重音削波。这个保护也用于离线渲染测试。音频上下文在首次用户点击或按键时创建和恢复，以遵守浏览器的自动播放限制。
